# Telegram-бот для сопровождения обучения

## О проекте

Telegram-бот помогает пользователю проходить обучение на внешней учебной
платформе и управлять напоминаниями. Бот взаимодействует с платформой
через HTTP API, а пользовательские настройки хранит в собственной базе
данных.

Проект построен на Python и `aiogram 3`. Асинхронные обработчики
Telegram отделены от клавиатур, работы с базой данных и сервисов
интеграции.

## Основные возможности

### Настройки обучения

Пользователь может:

-   включать и приостанавливать напоминания;
-   выбирать частоту напоминаний;
-   выбирать расписание получения напоминаний;
-   менять режим выбора следующего урока.

В интерфейсе предусмотрены два режима выбора уроков:

-   **Последовательный (`course_order`)** --- уроки предлагаются по
    порядку программы.
-   **Адаптивный (`last_completed`)** --- следующий урок выбирается с
    учётом последнего завершённого урока.

### Интеграция с учебной платформой

Бот обращается к API платформы, чтобы получить следующий урок, узнать
прогресс пользователя и изменить режим выбора уроков.

Ожидаемый контракт API описан ниже. Адрес API и способ авторизации
задаются конфигурацией проекта.

### Напоминания и опросы

Отправку запланированных сообщений следует выполнять отдельными
одноразовыми задачами. Например, Linux Cron может запускать скрипт
рассылки по расписанию. Такой скрипт не заменяет основной процесс бота и
не запускает polling.

Если в проекте используется ежемесячный опрос, его рассылку можно
запускать отдельной точкой входа, например `run_survey.py`. Саму логику
отправки целесообразно держать в сервисном модуле.

## API учебной платформы

Бот ожидает следующие эндпоинты. Примеры ниже описывают формат обмена
данными, а не адрес реального сервера.

### `GET /next-lesson`

Получить следующий урок пользователя.

Успешный ответ:

``` json
{
  "lesson": {
    "name": "Название урока",
    "url": "https://platform.com/lesson/123"
  }
}
```

Если доступных уроков нет:

``` json
{
  "lesson": null
}
```

### `GET /progress`

Получить прогресс пользователя.

Пример ответа:

``` json
{
  "user_id": 123456789,
  "progress": 65,
  "status": "in_progress",
  "last_activity_at": "2026-10-28T12:00:00Z",
  "has_pending_review": false
}
```

Поля `last_activity_at` и `has_pending_review` особенно важны для логики
напоминаний:

-   `last_activity_at` --- дата и время последней активности
    пользователя;
-   `has_pending_review` --- признак наличия ожидающей проверки.

Если эти поля отсутствуют или имеют другой формат, логика напоминаний
может работать некорректно.

### `PATCH /settings`

Изменить режим выбора следующего урока.

Тело запроса:

``` json
{
  "telegram_id": 123456789,
  "next_lesson_mode": "course_order"
}
```

Допустимые значения `next_lesson_mode`:

-   `course_order`
-   `last_completed`

Ожидаемый успешный ответ API: HTTP `200` с JSON или HTTP `204` без тела
ответа. Клиент должен корректно обрабатывать оба варианта.

## Установка и настройка

1.  Разместите проект на сервере.
2.  Создайте виртуальное окружение Python.
3.  Установите зависимости из файла проекта (например,
    `requirements.txt`, если он предусмотрен).
4.  Заполните конфигурацию: токен Telegram-бота, параметры подключения к
    базе данных, адрес API и необходимые данные авторизации.
5.  Убедитесь, что база данных доступна и схема создана/обновлена.
6.  Проверьте запуск бота вручную.

Пример команд для Linux:

``` bash
cd /path/to/project
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Команды предполагают наличие `requirements.txt`. Если зависимости
устанавливаются другим способом, используйте принятый в проекте способ
установки.

## Запуск Telegram-бота

Основной процесс запускается через `main.py`:

``` bash
cd /path/to/project
source .venv/bin/activate
python main.py
```

Этот процесс обычно работает постоянно и обрабатывает входящие сообщения
и callback-запросы пользователей.

## Запуск отдельной рассылки через Linux Cron

Одноразовую задачу рассылки нужно запускать отдельным скриптом, например
`run_survey.py`.

Разделение ответственности:

-   `main.py` запускает Telegram-бота и его обработчики;
-   `services/survey.py` содержит логику получения получателей и
    отправки приглашений;
-   `run_survey.py` создаёт экземпляр `Bot`, вызывает функцию рассылки и
    закрывает HTTP-сессию.

Пример точки входа `run_survey.py` (имена импортов и конфигурации нужно
привести в соответствие с проектом):

``` python
import asyncio

from aiogram import Bot

from core.config import BOT_TOKEN
from services.survey import send_monthly_surveys


async def main():
    bot = Bot(token=BOT_TOKEN)

    try:
        await send_monthly_surveys(bot)
    finally:
        await bot.session.close()


if __name__ == "__main__":
    asyncio.run(main())
```

Функция `send_monthly_surveys(bot)` должна находиться в
`services/survey.py`. Она выполняет рассылку и завершается. Важно:
пример предполагает, что `BOT_TOKEN` действительно экспортируется из
`core.config`, а сервис имеет указанную сигнатуру. Если в проекте
используются другие имена, поправьте импорты.

### Проверка ручным запуском

До добавления задачи в Cron запустите рассылку вручную:

``` bash
cd /path/to/project
/path/to/project/.venv/bin/python run_survey.py
```

Убедитесь, что скрипт отправляет сообщения, корректно обрабатывает
ошибки Telegram и завершается без зависших соединений.

### Добавление задачи в Cron

Откройте редактор задач текущего пользователя:

``` bash
crontab -e
```

Например, чтобы запускать рассылку первого числа каждого месяца в 10:00
по времени сервера, добавьте строку:

``` cron
0 10 1 * * cd /path/to/project && /path/to/project/.venv/bin/python run_survey.py >> /path/to/project/logs/survey_cron.log 2>&1
```

Замените `/path/to/project` на абсолютный путь к проекту. Каталог `logs`
должен существовать, а у пользователя Cron должны быть права на запись в
него.

Формат расписания Cron:

``` text
┬ ┬ ┬ ┬ ┬
│ │ │ │ └── день недели (0–7)
│ │ │ └──── месяц (1–12)
│ │ └────── день месяца (1–31)
│ └──────── час (0–23)
└────────── минута (0–59)
```

В примере `0 10 1 * *` означает: в 10:00 первого числа каждого месяца.

Cron использует часовой пояс сервера, если отдельно не настроен иначе.
Проверьте часовой пояс сервера и учитывайте его при выборе времени
запуска.

### Проверка Cron

Посмотреть сохранённые задачи:

``` bash
crontab -l
```

Проверить лог рассылки:

``` bash
tail -n 100 /path/to/project/logs/survey_cron.log
```

Cron запускает скрипт независимо от `main.py`. Не добавляйте запуск
`run_survey.py` в основной polling-процесс, иначе рассылка может
выполняться при каждом старте бота.

## Важные замечания для эксплуатации

-   Не храните токен Telegram и секреты API непосредственно в
    репозитории.
-   Убедитесь, что Cron получает те же переменные окружения и настройки,
    что и обычный запуск проекта. Cron обычно не загружает интерактивное
    окружение shell автоматически.
-   Используйте абсолютные пути к Python-интерпретатору, скриптам и
    логам.
-   Перед включением регулярного расписания проверьте одноразовый скрипт
    вручную.
-   Продумайте защиту от повторной рассылки, если задача будет запущена
    вручную несколько раз или Cron выполнит повторный запуск.
-   Ошибки отправки отдельному пользователю желательно логировать, не
    прерывая рассылку всем остальным получателям.
-   Для корректной работы напоминаний интеграция с платформой должна
    возвращать актуальные `last_activity_at` и `has_pending_review`.
